# hello-suna — the SUNA example project

The project a new SUNA install scaffolds for you, a few days in: the starter
manuscript is still there, but a second figure has been generated from code, a
supplement has been written, and a round of referee reports has come back and is
part-answered. **Every workspace view has real content**, and every artifact can
be regenerated from the files beside it.

It is also a joke about itself. The study is the effect of SUNA on one
researcher, the sample size is one, the participant was not blind to condition
and also wrote the software, and Reviewer #1 has noticed. The machinery
underneath is entirely real.

## What this project demonstrates

- **Manuscript as data** — `manuscript/` is flat: `manuscript.md` (the whole prose — sections are Markdown headings, and the opening is deliberately unheaded), `manuscript.json` (journal-agnostic metadata, validated by `@suna/core`'s `ManuscriptSchema`), `authors.json` (byline + affiliations) and `references.bib`. The outline is DERIVED from the Markdown, and numbering of figures, tables, equations and references is never stored — only derived from order plus the active profile (`suna.json` → `suna`).
- **Two figures, two provenances** — `figures/hello/` was drawn by hand and admits it; `figures/timesheet/` is generated by `source/plot.py` through `suna_mpl`, which writes a deterministic SVG with stable element ids the canvas can address, keeps text as real `<text>` elements so labels stay editable, rasterizes the dense mesh at 300 dpi, and emits the `figure.svg.suna.json` manifest mapping data coordinates to SVG ones.
- **A real analysis chain** — `data/happiness.csv` is processed by `analysis/fit_happiness.py` into `results/happiness_fit.json`, and the slopes quoted in Results come from that file. The model it imports lives in `code/`.
- **A notebook that is a scratchpad, not a pipeline step** — `analysis/explore_happiness.ipynb` opens as a real notebook tab and runs under the environment chip's interpreter. Six cells: it refits `data/happiness.csv` and checks the result against the committed `results/happiness_fit.json`, prints the verdict rather than writing a file, and deliberately draws no plot — the published version of that comparison is `figures/hello/`. It ships with no stored outputs, so running it is what fills it in.
- **A document set, not one manuscript** — `suna.json` declares a `documents` registry (ARCHITECTURE §4.2): the manuscript, the supplement and a cover letter. Letters live under `manuscript/letters/` so they inherit the comment gutter, versions and diff bar the manuscript has.
- **A letter that makes checkable claims** — the letter is prose (`cover.md`) plus a sidecar (`cover.json`). Factual assertions are structured in the sidecar and placed in the prose with `::assert{id}`, so "no repository named" is a fact the checker reads rather than a sentence it guesses at. One assertion is deliberately left unanswered, and shows a marker where it sits. The confidential suggested/excluded-reviewer list (`cover.private.json`) is gitignored by design and is therefore **not** shipped here — scaffold a starter project to see one.
- **A peer-review ledger** — `rounds/round-1/` holds a returned external round. The referees' words live in `reviewers/*.json`, cut into points by the offline importer, each one a byte-exact contiguous slice of the retained source. Nothing in the app offers an edit control for them.

## Where things live

`manuscript/` is prose you edit. `rounds/` is the ledger — records, snapshots
and verbatim received text, none of it hand-edited — and it sits at the
**project root**, not under `manuscript/`, which is the placement rule ARCHITECTURE §4.2
states once and everything obeys. A logged version is the one apparent
exception and is not one: `manuscript/archive/` holds copies of prose, so it
lives with the prose. This example has logged none — press **Log version** in
the Writing panel to make one.

## Directory map

| Directory     | Contents |
| ------------- | -------- |
| `manuscript/` | `manuscript.md`, `manuscript.json`, `authors.json`, `references.bib`, `supplementary.md`, `letters/` |
| `rounds/`     | the peer-review ledger: one directory per round (`round.json`, `reviewers/*.json`, `editor-letter.txt`) |
| `figures/`    | one directory per figure: `figure.svg` + `figure.json`, plus `source/plot.py` and a `.suna.json` manifest when the figure came from code |
| `data/`       | the timesheet and the happiness log, as CSV |
| `analysis/`   | pipeline scripts that turn `data/` into `results/` |
| `results/`    | machine-written analysis products (never hand-edited) |
| `code/`       | reusable model code imported by the analysis |
| `output/`     | formatted exports land here (generated; empty in the repo) |

## Regenerating everything

All commands run from this directory (`examples/hello-suna/`) and use the
`suna_mpl` environment via [uv](https://docs.astral.sh/uv/):

```bash
# 1. analysis products (results/happiness_fit.json)
uv run --project ../../python/suna_mpl python analysis/fit_happiness.py

# 2. the generated figure (deterministic SVG + .suna.json manifest)
uv run --project ../../python/suna_mpl python figures/timesheet/source/plot.py
```

Every step is deterministic: rerunning it reproduces the committed files byte
for byte. Figure 1 is not on that list, because Figure 1 was drawn by hand.

## The review round, and what it is showing you

`rounds/round-1/` is a returned external round with a `major-revision`
decision. Its `round.json` holds the **mutable half** — one `pointStates` entry
per referee point, carrying the author's status, assignee, reply and links back
into the manuscript. The **immutable half** is `reviewers/1.json`, `2.json` and
`3.json`, which retain the whole decision letter as `sourceText` and cut it into
points by offset.

Four things in there are deliberate and are not defects:

- **Reviewer 1's point 2 is `rebutted`, not `done`.** Disagreeing with a referee in writing is answering them; the counter at the top of the tab treats it as addressed. A tool that modelled only compliance would quietly press authors into conceding points they should defend.
- **Reviewer 1's point 3 is `drafted`, and stops mid-sentence.** A half-written reply is the normal state to be in, right up until you send it.
- **Reviewer 1's point 1 uses the response marks.** `::quote … ::` wraps manuscript text quoted back to the referee and `+++ … +++` marks the part of it that is new, which is what colours the three voices of a response letter apart at export.
- **Most points are `unaddressed`.** That is what makes the response checker report `response.point-unaddressed` by name the moment the round is opened — the whole reason the check exists.

The project is agent-ready (ARCHITECTURE §15.4): `AGENTS.md`/`CLAUDE.md` point coding
agents at the machine context layer, `context/` holds the project brief, memory
and rules, and opening the project in SUNA writes a machine-local `.mcp.json`
wiring its manuscript tools.
