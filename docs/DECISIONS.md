# Decision log

**How to read this.** Append-only and chronological: entries are `YYYY-MM-DD — decision — why —
alternatives rejected`, newest at the bottom. It records *why*, not what is true now —
`docs/ARCHITECTURE.md` is the only statement of the latter, and where the two disagree the
contract wins and this file is the history of how it got there. A later entry may supersede an
earlier one, and says so when it does. Large design rounds get a dated `##` subsection; small
decisions are one to three dense lines.

Dates come from the git authored date of the commit or document that carried the decision, or from a
date the document states about itself. Entries folded in from the eleven ADRs, the fifteen
`feature-plan-*.md` milestone plans (deleted after this file absorbed them), the design notes beside
them, `CHANGELOG.md` / `docs/RELEASING.md` / `docs/PACKAGING.md`, and the commit log.

## 2026-08-13 — the founding decisions (ADR-001, ADR-002, provenance loop, profile discipline)

### The canvas
- 2026-08-13 — The figure canvas is a custom SVG-DOM editor in `@suna/canvas` whose document model **is** the SVG DOM — DOMParser → mutate in place → XMLSerializer, unknown nodes preserved verbatim — journals consume SVG, matplotlib produces it and git diffs it, so a proprietary scene graph with SVG as an exchange format inverts the product — alternatives rejected: OpenPencil (Kiwi binary node tree, lossy normalizing SVG import, no stable matplotlib gid, Vue-only SDK), tldraw (non-permissive since v4), Excalidraw (proprietary scene JSON, SVG lands as an image), Penpot (a whole ClojureScript platform, not embeddable).
- 2026-08-13 — Take OpenPencil's *architecture pattern* only — document as a queryable tree, GUI editor and AI agent as equal clients of one structured command interface — without taking its code: its MCP/CLI/XPath agent interface is best in class while its stack and format are unusable — alternatives rejected: forking or embedding OpenPencil.
- 2026-08-13 — Canvas geometry is physical: `width="183mm"` plus a viewBox, matplotlib pt converted at 1 pt = 0.3528 mm, width presets from the active publisher profile — journal figure specs are stated in mm — alternatives rejected: pixel-native artboards.
- 2026-08-13 — Normalize the view, never the file: never run svgo on a source, treat `<use>`-referenced structures as opaque, and gate every commit with a parse → serialize → byte-diff round-trip test on untouched files — import conversion is the top-ranked risk to lossless round-trip — alternatives rejected: normalizing on import, svgo cleanup.
- 2026-08-13 — The engine document stays pristine off-DOM and the viewport renders a mirror clone re-synced after each mutation — one source of truth, and a drag preview cannot dirty it.
- 2026-08-13 — Text is edited through a positioned HTML `contenteditable` overlay that writes back to tspans on commit; interaction happens in one world space via CTM inverses; the agent interface and the GUI share an inverse-op command log — text editing, nested-transform math and undo integrity are the named risk areas — alternatives rejected: native SVG text editing, per-node local-space interaction.

### The formatter
- 2026-08-13 — Publisher profiles are scoped to what journals *state* in their author guidelines — citations, figure design rules, manuscript limits, compliance checks, clean submission export — never to the visual design of typeset pages; reference PDFs are grounding for defaults only — alternatives rejected: reproducing mastheads, two-column templates, running heads, drop caps and print pagination; journal-facsimile PDF/DOCX export.
- 2026-08-13 — Compliance checking flags violations (figure font too small, abstract too long, missing availability statement, off-palette colours) and never silently reformats — the author stays the decision-maker — alternatives rejected: auto-reformatting to the profile.
- 2026-08-13 — Descope the V2/V3 native chart-authoring "canvas capability" from reference-analysis §2 — figures are authored in matplotlib or imported, and the canvas adjusts, annotates and checks — alternatives rejected: a native chart-authoring engine.
- 2026-08-13 — The `@suna/core` profile schema is guideline tokens and limits with a source URL per field, not page-geometry and typography templates — profiles are populated from published guideline pages and must stay maintainable — alternatives rejected: the page-template schema (kept as documentation only).
- 2026-08-13 — A field recorded as `{ value: null, notStated: true }` emits nothing at all — no diagnostic, no default enforcement — silence in the guidelines is not permission to invent a rule.
- 2026-08-13 — Severity is derived from the source's own phrasing: `hard: true` or an unhedged limit is an error; `hard: false`, hedged wording, or an umbrella/flagship-sourced value is a warning — ApJL's limits are "no longer intended to be compulsory" and MNRAS says "normally … 250 words", so both degrade.
- 2026-08-13 — Every diagnostic carries a "why?" affordance showing the governing field's `note` and `sourceUrl`, and every profile value keeps the verbatim quote and the page it came from.
- 2026-08-13 — Errors block only the export dialog's final-submission path and stay overridable with acknowledgement; warnings never block — the checker is advisory, never a rewriter.
- 2026-08-13 — Third-party and secondary sources are excluded from profiles — the ApJL "5–6 page limit" that circulates in web summaries is not on the official page; where a publisher defers (IOP to AAS) the authoritative page wins.
- 2026-08-13 — Renderer-enforced rules (author-list truncation, reference-list order) fire diagnostics only on user-overridden or hand-edited entries — the renderer autofixes the normal path, so a diagnostic there would be noise.
- 2026-08-13 — `suna_mpl` width presets come from official author guidelines (Nature 88/180, Science 90/183) — supersedes the PDF-derived 89/183 measurements.

### The provenance loop
- 2026-08-13 — Canvas edits are recorded as an ordered, replayable overlay of **commands**, not DOM diffs — command-time recording captures intent (`translate legend by (4,-2)`) rather than effect (`transform="matrix(…)"`), and intent is what absorb needs to write sensible code — alternatives rejected: DOM diffing, kept only as the v2 "adopt external edit" fallback where intent is unavailable.
- 2026-08-13 — The overlay is restricted to ops replayable by target id (`set-style`, `set-attrs`, `set-text`, `translate`, `scale`, `reorder`, `delete`, `insert`) — interactive-only notions like selection have no meaning on replay.
- 2026-08-13 — An op whose target vanished moves to `orphans` and is badged in the figure panel — never silently dropped.
- 2026-08-13 — Absorb produces a unified diff a human reviews, never an auto-apply; deletion of an absorbed op is verified mechanically by attribute diff against the fresh base, not by trusting the model.
- 2026-08-13 — Hand edits to the generating script win and replay proceeds with no merge prompts — the overlay is always subordinate to code.
- 2026-08-13 — An external `.svg` edit marks provenance stale and offers adopt / detach / discard; v1 ships adopt as manual only.
- 2026-08-13 — `figure.svg` is always the current visual truth (base ⊕ overlay) and replay is a pure function — regenerating twice on the same data must produce a byte-identical file.

## 2026-08-14 — the editing suite, the flux review, and the first milestones

### ADR-003 and the interaction layer
- 2026-08-14 — Build the full Figma-grade editing suite — tool rail, drag-to-create, 8-handle resize and rotate, marquee, smart-guide snapping, properties and layers panels, in-place text editing, keyboard map — on our own engine, with every gesture compiling to the same command-bus commands the AI agent dispatches — the M2 engine already ships a byte-identical round-trip and a byte-exact inverse, which embedding a third-party editor forfeits, and OpenPencil's Vue 3 + Skia/CanvasKit stack cannot embed in a React + SVG-DOM renderer without a second rendering engine — alternatives rejected: OpenPencil "under the hood", any embedded third-party editor.
- 2026-08-14 — Treat OpenPencil (MIT) as a source-code quarry: port or reimplement its framework-agnostic interaction algorithms (handle math, snapping, marquee, keyboard model) with a source comment and NOTICE attribution where code is taken verbatim — the interaction algorithms are the reusable part; the document model is not — alternatives rejected: writing all interaction math from scratch; depending on OpenPencil as a library.
- 2026-08-14 — Everything in the interaction suite compiles to existing engine commands; the editing layer adds no new mutation primitives.
- 2026-08-14 — Split the suite into a framework-free interaction core (`src/interact/`, pure TS state machines and geometry) and thin React components — the core is testable without a renderer.
- 2026-08-14 — Text elements resize by font-size scale, not matrix transform — matrix scaling breaks publisher font-size guidelines; the properties panel is the primary size control.
- 2026-08-14 — New-element style defaults follow the active publisher profile (stroke within min/max, Wong palette order, compliant pt) — creation lands compliant instead of being flagged afterwards.
- 2026-08-14 — Gesture previews mutate only the mirror clone; commits dispatch engine commands and re-sync, and the properties panel reads the engine document, never the mirror.
- 2026-08-14 — Layer visibility toggles are recorded `set-style display` commands while lock stays UI-only state — visibility is a document fact, locking is not.
- 2026-08-14 — Acceptance for the suite is agent-drivable and ends in a byte-identical file after the undo chain — proof that the suite adds no hidden document drift.

### The flux review
- 2026-08-14 — Reimplement fluxplot's semantic-plot contract in `suna_mpl` from ideas only, never code — `fluxsci/fluxplot` carries no license while this repo is MIT and portable with attribution — alternatives rejected: porting fluxplot verbatim; depending on flux at all (bus factor ≈ 1, no community).
- 2026-08-14 — Adopt byte-deterministic SVG regeneration (pinned `svg.hashsalt`, `fonttype: none`, stripped dates, canonical ordering) — the provenance loop's reviewable diffs are meaningless unless regeneration is byte-stable.
- 2026-08-14 — Adopt per-axis (data, svg) anchor pairs in a sidecar manifest — an exact data↔pixel mapping including log axes, for data-space annotation — alternatives rejected: reconstructing matplotlib transforms.
- 2026-08-14 — Auto-rasterize a heavy layer above ~800 primitives per artist — flux measured 76k SVG nodes collapsing to 67, and our SVG-DOM canvas hits the same wall (~2.5 fps at 260k nodes).
- 2026-08-14 — Keep the `.svg`-is-the-document model against flux's counter-example of app-managed JSON referencing plot *copies* with derived renders — byte-identical round-trip is stronger and interoperable.
- 2026-08-14 — Keep the bundled-Tectonic export plan on flux's counter-lesson: requiring user-installed Quarto + TinyTeX means a fresh install cannot export. *(Superseded 2026-08-15: DOCX via the bundled `docx` library and PDF via `printToPDF`, no LaTeX at all.)*
- 2026-08-14 — Bake figure numbers, captions and references to literal text before the downstream renderer — once figure families (Fig / Supplementary / Extended Data) number independently, numbering must never be delegated.
- 2026-08-14 — Keep sourced JSON publisher profiles and extend them with per-value provenance tags (`counted-empirically` / `documented` / `inferred`) — Nature's printed panel style diverges from its own guidelines and nature.com self-contradicts, so both must be recordable — alternatives rejected: two hardcoded TS journal presets; a bundled 2.3 GB local-corrections model.

### The UI fix round
- 2026-08-14 — Introduce an explicit content kind (`prose` vs `code`) instead of treating every file alike — code was soft-wrapping mid-statement and floating right because it obeyed a prose width setting; code must never be wrapped, centered, or set in the body font.
- 2026-08-14 — Prose source mode left-aligns at the gutter while reading mode centres the measure — `margin-inline: auto` on the full-width scroller left the block at x≈950 px with the line-number gutter pinned at x≈270 px.
- 2026-08-14 — Hide the Font control on code tabs rather than letting it apply — code and data are always monospace.
- 2026-08-14 — One measure for the whole manuscript document (title page, sections and references share `--ed-content-width`) — observed a 1020 px title page against 430 px section editors inside one document.
- 2026-08-14 — Extract the gear popover into a shared `EditorSettingsButton` and mount it in the manuscript tab — settings existed only in `EditorTab`, so the combined tab ignored the user's choice and fell back to 68ch.
- 2026-08-14 — The *preview* profile drives in-text chips and reference-list sort and re-runs on `previewProfileId` change, not only on save — "Rendered as ApJ" showed author–year in the sidebar while the body still showed superscripts.
- 2026-08-14 — Cross-references resolve against a derived label map and an unresolvable id keeps its raw text with a warning style — never silently blanked.
- 2026-08-14 — The whole round is constrained to presentation: no file-format or engine change, and every fix gets a test at the level it lives (vitest for pure logic, smoke for anything only observable in the running app).

### Milestone decisions (feature-plan-2 / -3 / -4)
- 2026-08-14 — Every title-page field commit re-reads `manuscript.json` from disk, applies one change, validates, then atomic temp+rename — the file is the source of truth and an agent may have edited it — alternatives rejected: writing back a stale in-memory copy.
- 2026-08-14 — Affiliation superscripts renumber automatically; they are derived, never stored.
- 2026-08-14 — Comments live in a sidecar `comments.json` anchored by quote plus prefix/suffix, never as markers in prose, and a comment whose quote is gone becomes `detached` rather than vanishing — the manuscript text stays clean and diffable — alternatives rejected: inline markers.

- 2026-08-14 — Canvas rulers are in mm, and figure width presets come from the active profile's `figureRules.widthPresetsMm` — alternatives rejected: flux's hardcoded 190 mm.
- 2026-08-14 — PNG/TIFF export rasterizes the SVG in the renderer with a baseline uncompressed TIFF encoder, and PDF goes through main-process `printToPDF` — no new dependency, and the PDF stays vector.
- 2026-08-14 — The compliance checker runs before export and warns, never blocks.
- 2026-08-14 — Crossref is the default keyless literature provider and OpenAlex needs a key — measured: OpenAlex 429 "insufficient budget", Semantic Scholar 429, ADS 401, arXiv empty.
- 2026-08-14 — All network calls run in the main process (no renderer CORS/CSP problem) with keys in `safeStorage`, and every failure is surfaced verbatim with the provider switch inline — alternatives rejected: an empty result list pretending nothing matched.
- 2026-08-14 — Literature search can spawn the user's own `claude`/`codex` CLI headless, billed to their existing subscription — measured `claude -p --output-format json --allowed-tools WebSearch` returning correct DOIs while every metered API 429s; 8/8 results with DOIs in 129 s. Malformed items are dropped individually rather than failing the search, the budget is a hard 180 s, and cancel really kills the child.
- 2026-08-14 — MCP `search_literature` keeps the API providers only — an agent already has web search and must not recurse into another agent CLI.
- 2026-08-14 — Markdown formatting is marker toggling through a pure `toggleWrap` CodeMirror command, and every menu or shortcut action is one transaction so one ⌘Z reverts it whole; ⌘⇧C takes code because ⌘E is the mode cycle.
- 2026-08-14 — Comments move from an activity-bar view to a margin gutter beside the text (the Flux/Word model) — presentation only, store and MCP tools unchanged. Cards never overlap, off-screen anchors stick with a count badge, detached comments group at the top, and below 1100 px the gutter collapses to dots. *(Superseded 2026-08-17 by the right-side rail.)*
- 2026-08-14 — New figures get the active profile's double-column width at a 0.618 ratio; an imported SVG has its ids namespaced against collision and an imported PNG is embedded as a data-URI `<image>` at natural mm size at 300 dpi — each a single undoable command.
- 2026-08-14 — Split view is a command over dockview's existing position API and reuses the second group rather than nesting endlessly — never a second layout engine.
- 2026-08-14 — pdf.js runs in the renderer and never in main — it needs DOM (`DOMMatrix`) — rendering to `<canvas>` from bytes read over a root-confined `fs:read-binary`, so there is no iframe, no `file://` and no CSP relaxation — alternatives rejected: `frame-src` with a custom protocol.
- 2026-08-14 — In-flight `page.render()` is cancelled on zoom or scroll — a 300-page PDF must never leak canvases.
- 2026-08-14 — Reference-PDF resolution is a pure, tested function trying the BibTeX `file` field, then `references/<citekey>.pdf`, then an `Author_Year*` fuzzy match; "Attach PDF…" copies and never moves; auto-open sits behind a default-on preference and reuses the side group.
- 2026-08-14 — PDFs are read-only artifacts: SUNA never rewrites one. *(Superseded 2026-08-18 for reference PDFs, which are highlighted in place.)*
- 2026-08-14 — One command palette with prefix modes (none / `>` / `$` / `?`) over a command registry any feature can add to, so a new command needs no palette edit.
- 2026-08-14 — Live CDP testing against real Chromium is the fidelity gate, not jsdom — jsdom could not see the decimal char-ref escapes and xmlns reordering that broke byte-exact round-trip.
- 2026-08-14 — Bundle `@suna/bib` into the Electron main build rather than externalizing it — workspace packages ship raw TypeScript, so externalizing made Node load a nonexistent `.js` and killed the app at launch.

## 2026-08-17 — ADR-005, ADR-006, and the directed-AI milestones

### Export style and captions
- 2026-08-17 — The SUNA house style is the always-on export base for every profile (`SUNA_DEFAULT_STYLE` plus `resolveDocumentStyle` deep-merging a now-PARTIAL profile `documentStyle`), grounded in three real submitted manuscripts verified at OOXML level plus SLEEP's guidelines — the `isHouseStyle` fork had left twelve journal profiles on a legacy A4/Word-blue/full-grid look — alternatives rejected: the `isHouseStyle` boolean fork and its legacy style, and the "a journal profile is left completely alone" test invariant.
- 2026-08-17 — Journal differences are small typed deltas (`figureLabel`, `figurePlacement`, `tablePlacement`, `referencesStartNewPage`, typography), stated only where guidelines state them, `null` or absent meaning inherit, each sourced in the profile's notes — `documentStyle` is under the same source discipline as every other profile field — alternatives rejected: full per-journal style definitions.
- 2026-08-17 — Remove the external `docx-tools` accelerator (CLI detection, `export:tools-available`, the dialog checkbox) and port its logic into the bundled `docx` library — real numbering.xml lists, figure and table bookmarks with internal-hyperlink cross-refs, its back-matter order, keywords, neutral docProps — everything ships in-package.
- 2026-08-17 — Show journal-stated submission options rather than enforce them: the requirements panel summarizes required / do not use / not stated, and stated double-spacing or line-number values seed defaults without locking the checkboxes.
- 2026-08-17 — One SUNA caption standard in every renderer — live preview, reading view, HTML/PDF and DOCX: a bold derived "Figure N." with the italic caption centred below; for tables a bold "Table N." plus italic short title above and an italic "Note. …" line below — alternatives rejected: bare GFM tables with a detached trailing "Tables" section and per-renderer caption styling.
- 2026-08-17 — `![[tbl:id]]` joins `![[fig:id]]` as a SciMark block construct, written alone above a markdown table to bind it to its `manuscript.json` `tables` entry, which keeps owning the caption — captions stay out of the prose, and an unembedded managed table still renders in the trailing Tables section.
- 2026-08-17 — Figure and table numbering is derived from prose order of first embed appearance, with manifest order only as a tiebreak for anything never embedded — manifest array order did not match prose order, and numbering is derived at format time, never stored.
- 2026-08-17 — `tex-omml` is all-or-nothing: any unsupported LaTeX token returns `null` and the caller falls back to the italic literal — it never half-renders and never throws.
- 2026-08-17 — PDF and HTML exports carry the app's active theme; DOCX stays untinted, because a Word file is a collaboration surface.

- 2026-08-17 — The source docs are embedded into a checked-in `packages/agent/src/context/docs.gen.ts` with a 16-hex sha256, re-synced on hash change from `ensureSunaConfig()` at app start and MCP boot — embedded means they ride the Electron and esbuild MCP bundles with zero packaging config — alternatives rejected: shipping loose doc files needing packaging config.
- 2026-08-17 — `.mcp.json` is machine-local and gitignored, generated per install (packaged: `process.execPath` + `ELECTRON_RUN_AS_NODE=1`; dev: `node` + `dist-mcp`) — it bakes an absolute server path by construction, and running the app binary as Node removes the system-node requirement — alternatives rejected: committing `.mcp.json` to the project repo.

### Directed AI actions, help, and the filesystem
- 2026-08-17 — Directed actions pass `--mcp-config` and `--allowed-tools` explicitly — measured: without them the headless CLI has no MCP and no write tools — and prompts travel on **stdin**, so there is no argv size limit and the prompt text does not appear in `ps` (which then dictates locating the child by `--mcp-config` in the cancel smoke step).
- 2026-08-17 — Directed edit actions are claude-only; codex asks run `--sandbox read-only`, so the UI disables them with an honest reason.
- 2026-08-17 — AI run state lives in a store keyed by `comment:<id>` / `figure:<id>` / `repair`, not in component state — a comment card unmounts when deactivated and dockview detaches hidden panels, and a run must outlive both.
- 2026-08-17 — A comment's body IS the instruction for its fix (no extra input in v1); the fix must use `edit_manuscript` exact find/replace and never `write_manuscript`, and resolves only if fully addressed. The card's `composing` flag is never touched, because the agent's reply arrives through the `comments.json` watcher which `composing: true` would defer.
- 2026-08-17 — Figure captures keep the selection overlay visible on purpose — the gold boxes tell the agent what "the selection" means — and use mirror element rects because the mirror is layout truth; the prompt forbids regenerating from `source/plot.py` and requires preserving element ids.

## 2026-08-18 — ADR-007, study acquisition (a mention becomes a PDF-backed citation)

### The ladder and its honesty
- 2026-08-18 — A free-text mention resolves through one four-rung ladder — `already-present` → `copied-local` → `downloaded` → `metadata-only`, plus a fifth `unresolved` — and the agent must always report which rung it landed on — a citation is an attribution whose errors survive into print, so every outcome must be legible — alternatives rejected: silently picking the top hit.
- 2026-08-18 — Resolution queries all four keyless providers in parallel and merges on DOI → arXiv id → folded title, with per-provider failures carried by name in `errors` — OpenAlex's metered 429 must never reach the user as "no such paper". An exact DOI or arXiv hint is decisive; `citedByCount` breaks ties only and never outranks a better title match.
- 2026-08-18 — `cite_study` writes nothing at all on `low` confidence (top two scores within 10 %, or best title similarity under 0.5), returning alternatives with their DOIs and asking to be re-run — a wrong citation reads as a fact, propagates through the reference list and costs a published erratum, while a top-hit guess is invisible because the bibliography looks exactly as correct as a right answer; the cost of asking is one message.
- 2026-08-18 — Match confidence is enumerated and pessimistic: `high` requires byte-level or DOI proof, a filename-only match never exceeds `medium`, a title-words-only match is `low`.
- 2026-08-18 — A local file is copied *unasked* only on `high`, or on `medium` corroborated by a second distinct evidence id — a lone `filename-author-year` hit is `medium` on its own and "Smith 2020" names every paper Smith wrote in 2020, so the ladder would file whichever one sat in `~/Downloads` under this cite key and the mistake would surface at submission. Weaker matches ride back as candidates with path and evidence and are copied only via `fetch_pdf {"accept": "<path>"}`, restricted to a path the scan itself reported.
- 2026-08-18 — That rule is one exported function, `isAutoCopyable`, living beside the scan because both hosts gate on it — while it was private to `mcp/study.ts` the desktop References view asked the looser `confidence !== 'low'` and copied in the match the MCP verb deliberately refused: one feature answering one question two ways depending on which button was pressed.

### Layering, config and the scan
- 2026-08-18 — Layer by capability: `@suna/core` holds schemas, `@suna/bib` stays pure-plus-`fetch`, and anything touching `fs` or `child_process` lives in `@suna/agent/library/` — so one implementation serves both the desktop and standalone MCP hosts unchanged.
- 2026-08-18 — Config lives in `~/SunaConfig/library.json` (`$SUNA_CONFIG_DIR` overrides), roots stored `~`-prefixed and expanded at use time — the standalone MCP server has no Electron userData, so a userData store would make an out-of-app session scan different folders than the Settings pane shows.
- 2026-08-18 — The local scan is Spotlight (`mdfind` through `execFile` with an argv array, no shell) **plus** a bounded walk of user-configured roots, merged; Spotlight absent, off, or non-darwin is a `note`, never a failure — alternatives rejected: Spotlight-only; scanning the whole home directory (that reads mail, Desktop archives and synced work folders the user never offered).
- 2026-08-18 — The scan is cheap-first: filename scoring for every `.pdf`, then a 12-candidate byte budget reading the first 256 KB. Publisher PDFs carry XMP as uncompressed XML, so a raw-byte DOI/arXiv/title search genuinely works and no PDF parser is needed — alternatives rejected: a PDF parser, content hashing, an incremental index (bounds are `maxFilesScanned` 20 000 / `maxDepth` 6 with a `truncated` flag).
- 2026-08-18 — That byte budget goes to the filename-ranked candidates **and** to the ones whose names scored nothing — Zotero, one of the four default roots, files everything as `storage/<8 chars>/Full Text PDF.pdf`, a name no filename rule matches, so reading only the top 12 of the ranked list left `doi-in-bytes`, the strongest evidence there is, unreachable for exactly the layout that most needs it.

### Boundaries
- 2026-08-18 — Reads may leave the project only into configured roots or Spotlight, and containment is checked against what `open` will actually reach: roots and candidates are realpath-resolved, symlinks refused or re-tested at target, and only regular files opened — `resolve` folds `..` but not symlinks (`Papers/x.pdf` → `~/.ssh/id_rsa` passed under its own name), Spotlight indexes bundles, and `open()` on a planted FIFO hangs the scan, the IPC call and the agent turn.
- 2026-08-18 — Writes never leave the project: every destination goes through `resolveInside` *plus* a post-`mkdir` realpath re-assertion in `prepareReferencesDir`, because `resolveInside` is lexical and a symlinked `references/` walks straight through a string check. An existing destination is never overwritten (it returns `already-present`), and a copy never moves the user's file.
- 2026-08-18 — Every URL is gated at every hop: `httpGet` admits only http/https and refuses hosts denoting this machine or a private network, on the first request and on each redirect — the ladder follows addresses other people wrote, so a landing page could aim SUNA at `169.254.169.254` and get an internal response written into `references/<key>.pdf` with its ports reported to the agent.
- 2026-08-18 — Never attempt paywall circumvention: no Sci-Hub, no institutional proxies, no credential replay. A 403 is reported as a 403 — the alternative would make the app a liability to the researchers it is for.
- 2026-08-18 — Every outside-origin path, URL and thrown error reaching a tool result goes through `quoteExternalPath` / `describeExternalError`, with no exception list written in prose — a tool result is the one channel by which third-party disk content reaches a model, errno messages smuggle the same bytes by a second door, and a URL is the same trust class as a file name. A file named `Gunn1972\n\nnotes:\n <directive>.pdf` would otherwise reproduce the report's line structure inside the agent's context.
- 2026-08-18 — That rule is held by a lexing source-text gate (`external-paths.test.ts`) over five named files with an allow-list of reasoned exemptions and its three known blind spots written down — five review passes over finished, green code found 6, 5, 2, 6 then 4 unescaped sites, a sequence that does not converge. The exemptions ended by *exporting* `describeExternalError` so the second host could physically call it, on the lesson that an invariant some callers cannot satisfy will be violated by exactly those callers.

### Downloading
- 2026-08-18 — The download order puts mirrors before publishers and reads OpenAlex's whole `locations[]` array, never just `best_oa_location` — measured over ten specimens: `best_oa_location` alone got 4 of 10, walking every location got 8. That field names the *publisher*, the host most likely to refuse a script, while the arXiv and PMC copies beside it serve bytes; PMC ids are fetched through europepmc.org, which unlike ncbi serves a script real PDF bytes. Policy is `off` / `open-access` / `publisher`, default `publisher`, with `citation_pdf_url` existing only under `publisher`.
- 2026-08-18 — A failed download reports *why* as a typed value — `refused` (with `refusedBy`), `no-open-copy`, `unreachable` — classified from the HTTP **status**, never from error prose, and rendered by one shared `describePdfFailure`: a bronze-OA paper behind Cloudflare is one click away in a browser and a 1972 paper with no open copy is not, and a substring search for "403" silently reclassifies the day someone rewords a sentence.
- 2026-08-18 — One 60 s deadline for the whole `downloadPdf` call, created at entry and honoured by both the candidate loop and the redirect loop, with the 20 s hop timeout a sub-limit — otherwise six candidates × two requests × four hops × 20 s is twelve minutes of wedged IPC or a wedged MCP turn against a server answering every hop at 19 s. Exhaustion names every URL tried and every rung skipped, with its reason.
- 2026-08-18 — `$SUNA_CONTACT_EMAIL` joins the server environment (Crossref polite pool, Unpaywall's keyless API); absent, that rung is skipped and the skip is *reported* rather than dropped.
- 2026-08-18 — `cite_study` decides the cite key from the pre-ladder bib text via a dry-run append, runs the ladder, then re-reads the file fresh immediately before a single append — a 60 s download must not clobber what the app wrote meanwhile, and the `file` field must name the PDF actually written. Appending is additive, so it is automatic; nothing overwrites or deletes, and an existing entry is reused byte-identical.
- 2026-08-18 — The feature ships as one implementation with three callers: four MCP verbs, `library:*` IPC for the Settings pane, and the References row's *Find PDF*.
- 2026-08-18 — Drift gates pin `MCP.md`'s verb table to the `TOOLS` registry three ways (sorted arrays not sets, the advertised count, per-row input names and `?` markers read off each zod schema) — a `Set` comparison had shipped a duplicated `cite_study` row reading to agents as two verbs, and `fetch_pdf`'s undocumented `accept` was an input no agent would ever send, leaving the escape hatch invisible while the ladder reported uncopyable candidates.
- 2026-08-18 — `add_reference` treats only ENOENT as an empty bibliography — every other read failure was caught as `''` and became the base of a whole-file write, silently destroying the user's references.

## 2026-08-18 — ADR-008, reading notes (highlighting someone else's paper)

- 2026-08-18 — Reading notes live in a per-paper JSON sidecar at `references/notes/<citekey>.json`, not in `manuscript/comments.json` — different lifecycle, audience and volume (your research on someone else's paper vs. co-authors' review of yours); concretely the project-wide badge would read 300 across five papers, `state/comments.ts` rewrites the whole review sidecar per add, and `mcp/comments.ts` falls through to `'manuscript'` for an unknown target kind — alternatives rejected: `comments.json`; path- or fingerprint-keyed notes (fingerprints differ between two copies of the same paper, a documented Hypothesis failure).
- 2026-08-18 — Holding note prose in JSON is not ADR-006's caption regret, whose discriminator is "does this prose belong in the flow of a Markdown document the user edits?" — a caption yes, a note on someone else's paper no. The corollary is a hard rule: SUNA never appends prose to a Markdown file it does not own the buffer of, since `ipc.ts` has only whole-file write and `DocSession` autosaves `core.text()` unconditionally — alternatives rejected: a SUNA-written `notes.md` (silent permanent data loss).
- 2026-08-18 — Anchoring reuses `packages/core/src/anchor.ts`'s W3C `{quote, prefix, suffix}` selector verbatim, with the `detached`-never-deleted rule — anchors survive a PDF being replaced where stored coordinates do not; the field record is PDF++ storing position only, Obsidian 1.8.0's 0→1-based `data-idx` silently highlighting the wrong text, and Skim storing notes in xattrs that git, Dropbox and email all strip.
- 2026-08-18 — One anchor per **contiguous item run** (`runs[]`), not one `[from,to)` range — content order is not visual order in publisher PDFs (Nature 4.3 %, PLOS 4.5 %, ATLAS 4.7 % of adjacent body-line pairs splice foreign content), so a single range stores the splice as the quote, paints over unrelated text and copies the corruption into the manuscript; and because the quote is self-consistent it re-anchors perfectly forever and is never found. Cross-page selection falls out free.
- 2026-08-18 — One shared `buildPageText(items)` owns de-hyphenation and whitespace normalisation, called by both the anchor builder and the renderer's offset→geometry mapping so they agree by construction — Nature shows 596 item boundaries with no whitespace and 93 hyphenated line breaks in 9 pages, ATLAS 1,373 and 243 in 12; normalise once and store normalised, so the quote is both matching key and publishable prose. (The naive `items.map(i => i.str).join()` joins with commas and would poison every stored quote.)
- 2026-08-18 — Page index and highlight rectangles are derived at paint time from PDF user space and mapped through `page.getViewport({scale, rotation})`, never stored — rotation- and zoom-correct by construction, avoiding `getClientRects()` drift on spans fitted with `scaleX(var(--scale-x))`.
- 2026-08-18 — The stored page is a load-bearing search hint: resolution runs hinted page → ±2 neighbours → whole document → `detached`, never per-page independently — `anchor.ts` returns tier-1 on a single occurrence in whatever text it is given, so "the star formation rate" from page 3 would paint on pages 8, 12 and 19 too, on first use, with no drift and no PDF change.
- 2026-08-18 — Highlights are written as real `/Highlight` annotations into `references/<citekey>.pdf` in place, as you highlight, native like Preview — measured with `pdfjs-dist@6.2.108` (already in tree, Apache-2.0) writing `/QuadPoints /C /CA /T /CreationDate /Contents /Popup` plus an `/AP` so Preview and poppler render it, and `saveDocument()` keeping the original bytes a byte-for-byte prefix (four publisher PDFs; 25 rounds grew the Nature file by +3.42 % with all 25 still readable) — alternatives rejected: `output/<citekey>-annotated.pdf`; and, by amendment, the intermediate explicit embed command.
- 2026-08-18 — The pristine-baseline / truncate-and-rewrite embed model is **superseded**: pdf.js *can* delete, by staging `{ id, deleted: true, pageIndex }` under a `pdfjs_internal_editor_` key — `getNewAnnotationsMap` silently ignores any other key, which was the entire reason it looked impossible (measured: 119R deleted, 120R survives, still a byte-exact append). The baseline was a trap: once another application rewrote the paper it stopped matching and SUNA could never write that file again, with no recovery.
- 2026-08-18 — Highlights reconcile against the file as it is: `planSync` reads the file's own `/Highlight` annotations, matches notes by geometry and issues the minimum edit, every write an ordinary incremental append — which makes a foreign edit a non-event. Two tested properties carry the safety: an annotation no note claims is never touched (a deletion is only performed for a region the caller *names*, captured from the note's own rectangles before removal, because geometry cannot distinguish a foreign highlight from a deleted note's), and the main process holds one stateless invariant — the incoming bytes must begin with the file on disk right now. Measured end to end: SUNA green + blue, an external app appends red, SUNA removes green, blue and red both survive.
- 2026-08-18 — The sidecar stays the source of truth even with native annotations, because pdf.js writes no `/NM` (no stable identity for a thread or tag) and `/QuadPoints` is absolute page coordinates (nothing in the file can re-anchor when the PDF is replaced). Accepted cost: a tracked binary that changes as you read, roughly 1 KB per edit with an unreviewable diff — weighed and accepted by direction.
- 2026-08-18 — A normal open writes nothing: unchanged sha256 and extractor version means resolve against stored hints and paint, because reading a paper must never produce a git-modified file. When the PDF actually changed the sweep runs in memory and reports first, with four first-class outcomes — `anchored` silent, `moved` hint updated and listed, `ambiguous` refusing to guess, `detached` kept forever with quote, body, tags and last page. `ambiguous` needs one additive `locateDetailed()` beside `locate()`, since `bestOccurrence` returns the first on a tie with the caller unable to tell; the flag lands in JSON so the re-anchoring event is reviewable in `git diff`.
- 2026-08-18 — No derived Markdown and no OCR pipeline — `docling` is a 5 KB meta-package pulling torch and 320–390 MB of weights and is Python-only, `marker` is CC-BY-NC-SA and last on OmniDocBench, GROBID needs OpenJDK 21, PyMuPDF4LLM is AGPL, olmOCR wants ≥12 GB VRAM, Nougat is CC-BY-NC and repeats on ~1.5 % of pages, and hosted OCR uploads embargoed PDFs to a third party. Three findings kill the category outright: best text edit distance 0.025 (~1,250 errors per paper) with formula 0.278 and reading-order 0.101; provenance does not survive (`export_to_markdown()` returns a bare `str`); and converters drift silently between runs, breaking every anchor with no way to say what changed. It is also the external-runtime dependency already rejected when export dropped LaTeX and Tectonic.
- 2026-08-18 — pdf.js's own `getTextContent()` is used as an anchor substrate only, never a reading substrate — measured 50,931 chars in correct reading order with 0 paragraph breaks and 219 unresolved hyphenations on an 11-page CVPR paper, and 184,396 chars / 405 hyphenations / 46 combining-bar artifacts on a 38-page REVTeX paper: unreadable, and entirely sufficient to search, quote and re-anchor. The page stays the reading surface — alternatives rejected: a committed `references/text/*.txt` substrate (~185 KB of greppable paywalled full text per paper, rewritten on every extractor bump, reproducible from an already-committed input).
- 2026-08-18 — One `Copy` action producing plain prose (`quoteWithCitation`: inline Pandoc citation, sentence-final punctuation moved after the bracket, column line breaks flattened) replaces *Copy with citation* and *Quote into manuscript* — it should read as typed rather than pasted. The dedicated quote command's safety machinery was deleted rather than left unreferenced, so any future quote-into-manuscript path rebuilds the CodeMirror-transaction seam deliberately.
- 2026-08-18 — `NotesRail` reuses the manuscript rail's whole `cmt-*` class vocabulary and `railLayout.layoutSlots` but not `CommentsRail` itself — its props need a live `EditorView` and card positions come from `view.lineBlockAt().top`, and a PDF has no height map, so the list scrolls in document order. Replies and Resolve are absent on purpose (nobody resolves a note to themselves about someone else's paper); tags instead.
- 2026-08-18 — pdf.js's writer (`annotationStorage` + `saveDocument`) is used without its editor UI — `AnnotationEditorLayer` means a 163 KB `pdf_viewer.css` with 46 `url()`s into an 81-file image directory, selectors scoped to Firefox's viewer DOM, a 16-positional-argument undocumented `AnnotationEditorUIManager`, and a `.d.ts` that misdeclares `textLayer`.
- 2026-08-18 — Pages render with `annotationMode: DISABLE` and SUNA paints every highlight itself from the file's own `/Highlight` annotations, subtracting its own by geometric overlap — correcting an earlier draft's claim that Preview/Zotero-highlighted papers "open blank" (they never did; `ENABLE` is the default and paints anything with an `/AP`). ## 2026-08-19 — ADR-009, typed document kinds

### Registry and typing
- 2026-08-19 — A project holds a set of typed documents, and `manuscript` becomes the first entry in a registry rather than a hardcoded singleton — the entry *describes* the layout already on disk, so the change is additive and no existing project moves a byte — alternatives rejected: migrating existing projects; treating manuscript as a permanent special case.

- 2026-08-19 — Every editable document lives under `manuscript/` and the directory keeps its name (`manuscript/letters/cover-science.md`) — the renderer already grants the comment gutter, ⌘⇧M, three-way merge and AI-diff paint to any `.md` under that prefix, and `comments.json`/`revisions.json` anchor there, so a new kind inherits the whole editing surface on day one with zero renderer surgery — alternatives rejected: a top-level `documents/` directory (a comments-schema change, a migration of every `comments.json` on disk and five renderer path rewrites, to buy a tidier tree); one comments file with a `documentId` field (the path already carries document identity).

### Rounds, freezes and returns
- 2026-08-19 — A round is a first-class noun: two tracks, seven purposes, linked through `previousRoundId` — the project's history at the granularity a human thinks in, which git's commit graph is not — alternatives rejected: a bare `versions.json`, which answers half the ask.
- 2026-08-19 — A freeze is stored twice: an annotated git tag `suna/round/<id>` **and** a text snapshot at `rounds/<id>/frozen/` — the tag has nowhere to put the profile id or the `ExportOptions` a PDF was printed with, without which a reviewer's "line 99" is unresolvable forever; the snapshot makes a round self-contained with no git and through a shallow clone. A dirty tree at freeze records `dirty: true` rather than being fixed, and a no-git project skips tagging and reports the skip.
- 2026-08-21 — The freeze snapshot includes `comments.json` and `revisions.json` — supersedes the earlier draft that omitted them; the report's central section is a comment diff between two freezes, and deriving it from git makes it computable only when a repo exists and the file was committed at both ends, contradicting both "a round with no git still works" and `Freeze.dirty`. Snapshot primary, git fallback, never the reverse.
- 2026-08-21 — Returns anchor against the RENDERED freeze, not the Markdown: `frozen/rendered/<file>.txt` plus a rendered→source offset map, composed rendered→source→HEAD via `wordDiff` — supersedes the earlier claim that anchoring against `frozen/<file>.md` was "guaranteed to resolve", which was false for every comment touching a citation, cross-reference or figure label (`[@key]` renders as a superscript number, `![[fig:x]]` as "Figure 2"). The co-author read the exported DOCX; the exporter already holds both sides at emit time.
- 2026-08-21 — A span with no source counterpart never becomes a prose anchor: it gets `frozenAnchor: null`, an `uninterpreted` mark and a figure/reference retarget offer — a precise structural answer rather than a heuristic. A minimum-information floor sends sub-floor returns to a human as `detached` with the frozen quote, because real anchors run 1–504 chars and `locate()`'s tier-1 check would sail past a one-character quote and return a confident wrong answer.
- 2026-08-19 — `returns:import` reads all four channels real DOCX files use — comment sidecar parts, `w:ins`/`w:del`, highlight runs, prose instructions — through the existing `jszip`; the last two carry assignee and open state with no schema anywhere, so they are preserved verbatim as `uninterpreted[]`, because interpreting a colour as a person would be inventing meaning while dropping it loses the lab's actual convention. Author identity is never trusted: all twelve real comments carry one `w:author` while five bodies name someone else, so `claimedAuthor` is a suggestion shown with its reason.
- 2026-08-19 — Returns are never written back and tracked changes are never auto-applied: DOCX and PDF stay export-only, returns land as reviewable hunks, and three returned files against one freeze produce three independent records — alternatives rejected: an N-way annotation merge (per-item triage is honest about ambiguity instead of silently picking a winner); git branches as the primary sharing mechanism (every co-author in the evidence is a Word user with no tooling; branches are an optional second channel); reusing `revisions.json` unwidened (`RevisionAuthorSchema.kind` is `z.literal('ai')`, and widening the enum buys the whole shipped accept/reject UI for one union member).
- 2026-08-19 — Measurements are observations carrying a fingerprint, never stored numbering; a stale fingerprint reports STALE, never truth.
- 2026-08-19 — The round report writes into a begin/end managed region: a file with no markers is the user's and is not written, and one marker, or reversed or duplicated markers, fail loudly — that is how a half-deleted marker eats a co-author's notes. `suna:agent-stub` is the opposite (whole-file) shape and is not a precedent.
- 2026-08-19 — The internal round report is fully derived from `{ from, to, include }` and rendered through the `export-notes.ts` pattern, and is stated honestly as an invention: no artifact in the evidence set is an internal round report, so there is no shape to imitate. Its justification is that every input is already on disk, so unlike a hand-written status email it cannot go stale.

### Reviewer points and letters
- 2026-08-19 — A reviewer point is not a comment, and its verbatim text never lives in an author-editable file: reviewer text in `rounds/<id>/reviewers/*.json`, replies in `manuscript/reviews/<id>/response.md` — editing a reviewer's words is misconduct, and this makes immutability structural rather than a rule to obey. - 2026-08-19 — `rebutted` is a first-class point outcome counted as addressed — a tool that only models compliance quietly pressures authors to concede points they should defend.
- 2026-08-19 — Cover-letter factual assertions (dual submission, competing interests) are a structured form only a human fills, never AI prose, and an unanswered required one blocks export — an agent may draft the argument and never sign the affidavit; the checker reports absence and never writes one, and no MCP verb can write an assertion or a reviewer's word.

- 2026-08-19 — A letter has no stored `date`; it is derived from the clock at export, which prevents the stale date baked into the user's own filename.
- 2026-08-19 — The abstract seed is inserted as an agent **comment** on the paragraph, not as prose — it reuses the comment path and keeps the checker from checking its own output.
- 2026-08-19 — Confidential reviewer lists live in `<id>.private.json`, gitignored via `ensureGitignoreLine` called BEFORE the file is written — that sidecar holds other people's names, emails and conflict reasons, so a file-first order leaves a window where `git add -A` commits it; `PROJECT_GITIGNORE` is written only at scaffold and docx-import, so pre-existing projects would otherwise never gain the stanza. ## 2026-08-19 — ADR-010, sponsor package assembly

### Registry and shape
- 2026-08-19 — A package is two ADR-009 document kinds — `package` (which slots this application fills, plus the facts gating conditional ones) and `component` (each authored slot) — so every component inherits the editor, comments rail and AI-diff review for free. An NIH application is not a document: the PHS 398 form prints thirteen numbered slots of three incompatible kinds.
- 2026-08-19 — The slot schema is profile data in its **own** registry (`resources/package-profiles/*.json`, `PackageProfileSchema`) — slots, per-slot measurement units, conditional triggers and *enforced* typography have no counterpart in an author-guideline profile; `PublisherProfileSchema.schemaVersion` is `z.literal(3)` with no version-tolerant loader, so a new required field forces a v4 plus a rewrite of thirteen JSONs, and a test hard-asserts the journal registry is exactly twelve journals plus the house style — alternatives rejected: folding sponsor rules into `PublisherProfileSchema`; a `pageLimit` field on `ArticleTypeRulesSchema` (one number per article type cannot express four measuring instruments over twenty slots — the limit belongs on a slot, with its unit).
- 2026-08-19 — Sponsor rules are swappable profile data over one shared substrate (aims prose, figures, `references.bib`, person roster), never a global setting — NSF conflicts with NIH almost everywhere they overlap: 15 pages vs 12, 1-inch vs half-inch margins, Arial 10 pt legal at NSF and illegal at NIH, a three-part Project Summary vs an unstructured 30-line abstract, a flat URL ban in the Project Description.
- 2026-08-19 — Slot conditions are five operators (`always`/`never`/`is`/`nonEmpty`/`gt`) over `package.json` facts, so every condition stays auditable in a JSON file a human must read, with operator/value compatibility checked at profile load so a bad condition fails loudly instead of never firing — alternatives rejected: a generic expression language (five operators cover every observed trigger).
- 2026-08-19 — An absent fact is UNKNOWN, not false: it reports `pkg.fact-unanswered` rather than quietly not firing. Empty slots keep their ordinals, because the real form leaves six of thirteen empty and never renumbers.
- 2026-08-27 — `subrecipients` joins `PACKAGE_FACT_IDS` and a fact value widens from boolean to `boolean | string | number | string[]`, so one non-empty fact fires both the Consortium narrative slot and the R&R Subaward Budget form slot — corrects an earlier example written against a fact that did not exist and a `partialRecord(enum, boolean)` type over which `nonEmpty` and `gt` could never mean anything. The example's third consequence, "and adds a performance site", is removed as an inference presented as a rule.

### Measurement
- 2026-08-19 — The applicant never paginates and SUNA measures what it did not number: the component recipe emits naked attachments (both agencies forbid applicant headers, footers, page numbers and TOCs because they assemble and paginate themselves) and then reads the page count out of the bytes it just produced. That inversion is the mechanism.
- 2026-08-19 — Page and line limits are measured on the rendered PDF, never estimated: split `exportPdf` into `renderPdfBytes` plus a thin writer and put an eight-line `pdfPageCount(bytes)` between them — `printToPDF` already holds the PDF as a Buffer in main and throws away the pagination Chromium just computed, while `pdfjs-dist` is already a dependency already dynamically imported in main. No new dependency, process, disk round-trip or estimate — alternatives rejected: estimating pages from word counts, exactly the invented threshold ADR-002 forbids.
- 2026-08-19 — Line counts come from the same render by factoring out the existing `getClientRects()` grouping; sentences, words and characters stay pre-render text counts. `export:package` answers per component with `{ slotId, file, pages, limit, over }` — the first export response that is not a single `{ path }`.
- 2026-08-19 — When `document.fonts.check()` reports substitutions, SUNA reports "page count unreliable — <family> was substituted" INSTEAD OF a number, and a DOCX target reports `pages: null` / "not measured" — a wrong page count on a grant application is worse than no page count; the print window sets no font preferences today and the bundled `docx` library writes no pagination.
- 2026-08-19 — Word-parity is fixed rather than disclaimed: `documentStyle.figureFloat` as CSS `float` in `pageCss`, because the real Research Strategy wraps figures beside body copy while SUNA places them inline at full width, so a 12-page Word document can report 13. Until it ships, the diagnostic must say it measures SUNA's inline layout. Risk is bounded for NIH, where PDF-only means the measured PDF *is* the submitted artifact.
- 2026-08-19 — Measurement runs behind an explicit "Check package" action and on export, never on keystroke, with one reused hidden `BrowserWindow` and a content-fingerprint cache — a Chromium print costs 0.3–1.5 s per component, and it cannot run headlessly at all today because figures rasterize in the renderer, so `measure_package` can only report cached measurements until a raster cache exists.
- 2026-08-19 — The package printer follows `export-pdf.ts`, never `figure-export.ts` — the latter passes `printToPDF` a `pageSize` in microns where Electron documents inches, inert only because `preferCSSPageSize` wins; copying it gives a silently wrong page size.
- 2026-08-19 — SUNA writes N separate files and never merges PDFs; the `merge` slot kind is the different, cheaper thing — it concatenates N *prose* documents before a single render (how the real submission's three letters of support arrive as one attachment) and is `documentIds` only, so it cannot smuggle in an `external-pdf` member. Merging rendered PDFs needs a new dependency (`pdf-lib`, named so it is not re-litigated), both agencies take N uploads and paginate themselves, and a merged preview must never be used for the limit check because re-rendering changes pagination.

### Typography, checks and boundaries
- 2026-08-19 — Numbering scope is per-slot (`referenceScope: 'slot' | 'package'`), reusing the independent-numbering shape `buildSupplementContent` already proves — the real package's Bibliography runs past 60 entries while Vertebrate Animals restarts at 1; figure and citation numbers stay derived, with field evidence of drift between the Word draft and the submission ("Figure 3" became "Figure 2", superscript 40–42 became 33–35).
- 2026-08-27 — Sponsor typography travels through a named conversion, `resolvedStyleForSlot(packageProfile, slot)`, and `PackageSlotSchema.documentStyle` is removed in favour of `formatOverride: PackageFormattingSchema.partial()` — supersedes the earlier "gains a second `override?` parameter" seam, which could not carry it: `resolveDocumentStyle` takes a `PublisherProfile` a package does not have, and a `DocumentStyle` override is the wrong type, unable to express per-side margins. Sponsor geometry never travels as a `DocumentStyle`, so the two registries need no common profile type. Sponsor `documentStyle` is legitimate under ADR-005 because NIH and NSF state their geometry precisely: sourced and enforced, not house style.
- 2026-08-27 — `ResolvedDocumentStyle.page.marginMm` widens to `{ top, right, bottom, left }` — NIH's and NSF's uniform margins fit a scalar only by luck and the package profile already declares per-side; the call sites are enumerable and small.
- 2026-08-19 — Checks split pre-render (deterministic and live: font, margin, density, word/char/sentence limits, forbidden URLs, missing headings, forbidden content) from post-render on measured bytes (`pkg.page-limit`, `pkg.line-limit`, `pkg.font-substituted`, `pkg.page-unmeasured`). Three earn their place by failing the real submission: `pkg.heading-missing` (the submitted Research Strategy uses its own headings where NIH prescribes Significance/Innovation/Approach — flagged, never rewritten), `pkg.schema-superseded` (`effectiveFrom`/`effectiveUntil` against `dueAt`; the real DMS Plan used a format replaced weeks before its deadline), and `pkg.term-inconsistent` (the real package names three different activity codes across its components — the same engine as ADR-009's `letter.journal-name-mismatch`, one implementation for two asks).
- 2026-08-19 — Filenames are generated by the exporter, so agency naming rules are a guarantee for authored files and only a check for stapled external PDFs — all nine real biosketch filenames pass NIH's rules and no two follow the same convention.
- 2026-08-19 — The rendering/stapling boundary is explicit: `external` slots are byte-copied under a compliant name with sha256 recorded and their page count still measured, and where pdf.js does not expose a fact the diagnostic says "not verified", never "passes" — SUNA never claims to have validated the inside of a stapled PDF.
- 2026-08-19 — Biosketches, budgets/SF424 and the institutional routing layer are out of scope — NIH mandates SciENcv with no blank template, form slots are structured data submitted through eRA/Research.gov, and routing pages are useful metadata in the wrong schema. The manifest records `source: 'form'` so the completeness checklist stays honest, `cardinality: 'per-person'` keeps the pairing rule checkable, and the package carries `dueAt` only so `effectiveFrom` is evaluable — alternatives rejected: LaTeX/Tectonic for components, since a second layout engine means two page counts that can disagree, the worst outcome for a check whose whole value is authority.
- 2026-08-19 — No `extends` for package profiles in v1 — the journal loader's `extends` replaces arrays wholesale, so a twenty-slot package cannot restate its `slots` array to change one limit and would need merge-by-id, and two merge semantics in one codebase is a real hazard. NIH R01 and NSF ship standalone.
- 2026-08-19 — Content reused across slots is recorded (`derivedFrom`) and diffed on demand, never propagated — the Project Summary is a lightly edited derivative of the Specific Aims and the divergences look deliberate; any drift threshold would be an invented number.
- 2026-08-27 — Sponsor provenance carries a fetch date plus per-slot `effectiveFrom`/`effectiveUntil`, not a content hash — sponsor rules move faster than journal rules (NIH changed the DMS format mid-cycle by Guide Notice), but hashing a page behind an intermittent IdP redirect would report false staleness.
- 2026-08-27 — Where the encoded rules are known-incomplete, the Compliance panel says so instead of showing green: "checked against the parent R01 table; this NOFO's Section IV has not been encoded" (NIH states NOFO Section IV supersedes the page-limit table, and that section was never fetched) and "checked against base PAPPG 24-1; supplements NSF 26-200 and NSF 26-202 have not been encoded" (one returns 404, reproducing today). The NSF profile id keeps the base document's name so the file cannot imply it covers more than it does.

### GitHub sign-in
- 2026-08-19 — Use an OAuth App, not a GitHub App, despite GitHub's general advice — a GitHub App cannot `POST /user/repos` (the primary flow would not work), can only push where installed (a co-author's org would need an admin install mid-paper), and its user tokens expire in eight hours needing refresh rotation, pure overhead for a desktop app with an OS keychain; GitHub Desktop and `gh` both do this — alternatives rejected: a GitHub App with fine-grained permissions.
- 2026-08-19 — Authenticate with the OAuth 2.0 device flow, which needs only the public client id, so nothing confidential ships — alternatives rejected: the web/redirect flow, which requires a client secret bundled into a downloadable binary and therefore is not a secret.
- 2026-08-19 — `BUILT_IN_CLIENT_ID` is committed to version control and overridable by `SUNA_GITHUB_CLIENT_ID` — the client id is public information and forks need their own — and the configured id is validated up front including the pasted-client-secret case (40 hex chars), which GitHub would otherwise reject with an error naming neither problem.
- 2026-08-19 — Scopes are `repo read:org` — `repo` is the narrowest that covers creating and pushing to a private repo, since OAuth Apps have no finer grain, and `read:org` only powers the owner picker and degrades gracefully. Nothing requested grants deletion.
- 2026-08-19 — Sign-out deletes the keychain token but does not revoke server-side — GitHub's revocation endpoint authenticates with `client_id:client_secret` and a public client has none; the panel points the user at github.com/settings/applications.

- 2026-08-19 — An empty `credential.helper` resets git's helper list for SUNA's invocations — osxkeychain answered before `GIT_ASKPASS`, so the OAuth token was never used; demonstrated by authenticating successfully while passing the literal string `totally_invalid_token`.

### ADR-011 and feature-plan-15: co-authors
- 2026-08-21 — Collaboration ships in two tiers in order — Tier 1 GitHub collaborator invites plus a clone-a-project entry point, then Tier 2 live prose over a relay — and Tier 1 remains the durable layer forever, since live sessions are ephemeral and git is what persists: turn-taking is what a manuscript mostly is, and git already handles it with reviewable diffs, attribution and history — alternatives rejected: Tier 1 as a throwaway stepping stone; going straight to live editing.
- 2026-08-21 — The GitHub repository is the access-control list: a person may edit iff GitHub says they are a collaborator, and the relay validates a joiner with one `GET /repos/{owner}/{repo}` call using their token, which it never stores (positive membership cached for the session's life, for rate limits) — the largest available scope reduction, and the existing `repo` scope already covers collaborator management so no existing user re-authenticates — alternatives rejected: SUNA accounts, a user table, our own invite tokens.
- 2026-08-21 — `admin` permission is deliberately not offered — transferring control of a repository is done on github.com, deliberately, not from a dropdown in a writing app — and "already a collaborator" (204, no invitation) is reported as success, not as nothing.
- 2026-08-21 — Clone offers the repositories the signed-in account can already see rather than demanding a URL; a project with no remote gets the publish flow, not an error.
- 2026-08-21 — Live text is central-authority OT over CodeMirror `ChangeSet`s against a version number, serialized and rebased by a relay — the vocabulary `DocSessionCore` already speaks — accepting that a disconnected peer cannot join a live session and goes through git as a reviewable diff — alternatives rejected: Yjs/Automerge CRDTs, which introduce a parallel document model with the file as a projection (the same rule that forbids a parallel scene graph), interleave two rewrites of one sentence into a non-sentence under character-level unconditional merge, and move durability into CRDT history so the file stops being truth.
- 2026-08-21 — `@codemirror/collab` is a reference implementation to read, not a dependency — it assumes one `EditorState` per client while SUNA has one hub with N views — so the network bookkeeping goes in the hub, generalizing the existing IME `pending` rebase field.
- 2026-08-21 — Live changes must NOT go through `applyExternal`, which diffs whole strings: that is right for "the file changed underneath us" and lossy for "here is precisely what my co-author typed".
- 2026-08-21 — Sessions are ephemeral and the relay is stateless: text and update log in memory only, created on the first peer and destroyed on the last, no database, disk or backups — losing the relay loses a session, not a manuscript, because every peer's converged text is already on disk via the existing autosave cadence, which is also what makes every peer's clone converge byte-identically without a new save path — alternatives rejected: any server-side persistence; a hosted-documents model with projects in our cloud, which is a different product that deletes what makes SUNA worth using.
- 2026-08-21 — The relay, not the host peer, is the session authority, so every peer's disk converges to the same bytes and any of them can commit while others fast-forward — alternatives rejected: host-peer authority (smaller diff, and no text leaves the owner's machine, but the session dies when the owner closes their laptop and guests edit the owner's files while their own clone sits unchanged).
- 2026-08-21 — A session is seeded by the first peer's buffer plus its commit sha and later joiners are admitted only at that sha, so the document always starts from something both sides could have produced from the same commit; a mismatched peer is rejected `behind-head` with a "pull first" button, and every rejection is a typed `Rejected` message, never a dropped socket.
- 2026-08-21 — The relay runs as a single small always-on Node process or one Cloudflare Durable Object per session, self-hostable and optional, configured by a single settings string that is empty by default — with none configured the app is exactly what it is today — alternatives rejected: Vercel/serverless functions (neither long-lived WebSockets nor in-memory per-session state), a mandatory relay.
- 2026-08-21 — Only prose goes live (`manuscript.md`, supplement, letter bodies, and comments in a later stage); never figures, `.bib` or `manuscript.json`, which are structured, edited rarely and deliberately, and covered by git. Comments sync as id-keyed operations with last-write-wins per field rather than as document text, because `comments.json` is append-mostly and anchored by quote rather than offset.
- 2026-08-21 — Live figure co-editing is permanently out of scope — figures stay single-writer, coordinated through git, and two people touching one SVG get a git conflict; live canvas editing would force a parallel scene graph and break ADR-001, and this clause is what keeps the feature affordable — alternatives rejected: deferring it to "later" or post-v1.
- 2026-08-21 — On disconnect the buffer keeps its text, the file is saved, and divergence becomes a git problem handled by existing machinery; a live session pauses the pump while an agent holds the file.
- 2026-08-21 — Correctness is decided headless by seeded convergence fuzz before a socket exists — wrong OT loses text silently, so convergence is asserted rather than eyeballed.

## 2026-09-01 — notebooks: `ipykernel` is offered, and where it cannot be, the failure says so

- 2026-09-01 — ROADMAP item 5 / §20.6 is closed **in onboarding and in the kernel's own startup path**, not in packaging. The earlier entry's reasoning was right and is preserved: the bridge runs under the *project's selected interpreter*, so there is no location to stage `ipykernel` into and no packaging change could have fixed it. What was missing was that the bridge enumerated a `pip install ipykernel` remedy nobody ever ran — advice handed to the user at exactly the moment they wanted to run a cell.
- 2026-09-01 — The shape is **one primitive, one channel, two asking callers**. `installKernelRuntime(envPath)` (`main/services/envs.ts`) does `uv pip install` with a `python -m pip` fallback; `env:install-kernel` is its only transport; the callers are the wizard's env sub-step and the notebook's "no kernel" panel. Three separate install paths were rejected — the *policy* differs between callers, the mechanism does not, and duplicating the mechanism is how two of them come to disagree about what "installed" means.
- 2026-09-01 — **The claim is `importable`, never `installed`.** The primitive probes `import jupyter_client, ipykernel` *after* the install as well as before, because a pip that reports success into a different interpreter, or a wheel that half-landed, is indistinguishable from a working kernel at the exit code. Reporting a green install that then fails at the first cell would be worse than the gap being closed.
- 2026-09-01 — **The three wizard branches are not equivalent, and the defaults say so.** "Create with uv" is an environment SUNA is about to create, so the offer is checked by default — provisioning something we made is not a surprise. An **existing detected environment is the user's**, possibly shared with other projects, so the offer is present but **unchecked**, and its label names the path it would write into. Silently installing into a detected environment was rejected outright: it is a side effect on something SUNA did not create, it cuts against D9 and against D5's "nothing is written until confirmed", and the failure mode — a shared env quietly gaining a package because the user created an unrelated project — is exactly the kind of thing a tool never gets forgiven for. "Skip" is offered nothing at all and told why, rather than shown an inert checkbox.
- 2026-09-01 — Also rejected: **installing at kernel-start time, automatically, on first failure.** It would have covered every branch with no wizard change, and it is the wrong trade — it turns pressing ⇧⏎ into an unannounced network write into the user's interpreter, with no place to have said no, and it would fire on a machine where the correct answer is "this interpreter is managed by your distribution, do not pip into it". Offering and confirming beats silently installing, at both call sites.
- 2026-09-01 — Also rejected: **writing a `requirements.txt` naming `ipykernel` into every new project** so the existing `provisionProjectEnv` path would pick it up. It reuses machinery, but it puts a SUNA-shaped dependency file into the author's repository to work around a SUNA problem, and `requirements.txt` is the author's declaration of what their *analysis* needs — not a channel for the editor's own runtime.
- 2026-09-01 — **The notebook's fault panel is kept even though onboarding now handles the common case**, and it is not redundant. The interpreter is a per-project pick changeable at any time from the status bar; projects also arrive by clone and by DOCX import, which never see the wizard; and an install can fail on a machine with no network. So the kernel path degrades on its own terms rather than assuming onboarding ran — the panel offers the same one-click repair against whichever interpreter is selected *now*, and where it cannot repair (no env selected, no network, a read-only interpreter) it says so and names the command.
- 2026-09-01 — `bridge.py`'s remedies now name **`sys.executable`** rather than saying `pip install ipykernel`. SUNA chose the interpreter on the user's behalf, so "run pip" is advice they cannot act on without first guessing which pip — and on a machine with a system python, a conda base and two venvs, guessing wrong installs the package somewhere that changes nothing.
- 2026-09-01 — A real bug fell out of proving this end to end, and is fixed here: the wizard's uv branch **created** `.venv` but never **selected** it, leaving the selection to the asynchronous detection pass that runs on project open. That pass does find it, but the renderer can start a kernel first — so the first notebook in a freshly provisioned project ran under the system `python3` and failed with `no-jupyter-client` *in the very environment onboarding had just provisioned*. SUNA made the env; SUNA names it, synchronously, in the same sub-step. This is D13 earning its place: the static reasoning said the detection pass covered it, and the driven run said otherwise.
- 2026-09-01 — Proof is `scripts/e2e/probes/notebook-kernel-onboarding.mjs`, which drives the **real** wizard (no stubbed install), takes the uv branch, and asserts the **output text** of an executed cell — `kernel ran: 42` — because "the kernel went idle" is exactly the kind of green that hides a broken runtime. It then proves the honest-failure half against a project whose selected interpreter has no `ipykernel`, and finally clicks the repair button and re-runs the cell: offering a fix that does not fix anything would be worse than the plain message. It is a probe and not a `pnpm smoke` step for that suite's own stated reason — adding steps to a suite that does not finish looks like coverage without being any — and because it needs `uv` and a network, which a unit gate must never require.

## 2026-09-01 — in-app updates

- 2026-09-01 — **SUNA updates itself, through `electron-updater` against the GitHub Releases `release.yml` already publishes** (ARCHITECTURE §23). Until now a user who downloaded 1.0.0 had no way to learn 1.1.1 existed short of visiting the repository, which for a desktop app shipped outside any store means most installs stay on whatever version they arrived as. The feed costs nothing new: `electron-builder.yml` already carried a `publish:` block, so `latest-mac.yml` / `latest-linux.yml` were already being written and attached — they were listed as *optional* assets "for a future in-app updater". They are now **required**, because a release missing one is a release that silently stops updating every install that reads it.
- 2026-09-01 — **The shape is main-owns-the-network, renderer-sees-small-JSON**, the same split every other service here keeps: an `UpdateStatus` of a phase, two versions, plain-text notes and a `received`/`total` pair. Bytes never cross the bridge and nothing installs without an `update:install` call carrying a click. Alternative rejected: letting the renderer drive electron-updater directly through a thin passthrough — it would put the installer one prototype-pollution bug away from the web content, for the benefit of deleting a fifty-line service.
- 2026-09-01 — **Three postures, decided from facts rather than preference** (`updateMode`): `inplace` for a packaged macOS build or an AppImage launch, `notify` for a `.deb`/`.tar.gz` where the package manager owns the install and SUNA may only *say*, and `off` for a dev tree or a driven `SUNA_HIDDEN=1` run. The `notify` check reads the same `latest-linux.yml` electron-updater would, over `net.fetch`, so the two paths can never disagree about what is newest. Deliberately **not** a signing check: a packaged-but-unsigned contributor build checks and fails honestly at install time, which is better than a build that silently never offers anything.
- 2026-09-01 — **`updates.checkOnLaunch` gates the automatic check only, never the mode.** A user who switches it off can still press Check now — asking is the user reaching the network, not the app doing it on its own. It lives in `config.yml` because it is a preference; the **skipped version** lives in `settings.json` because it is machine state nobody would hand-edit, and it silences exactly one version: a newer release announces itself again, and a manual check clears it, because asking again *is* un-skipping.
- 2026-09-01 — **Nothing downloads without a click** (`autoDownload = false`) and nothing installs before an artifact has landed, but `autoInstallOnAppQuit` is on: a user who pressed Download and then went back to work gets the update on the next quit rather than being asked twice. Also: a check never runs over a download (a `checking` push would blank the progress the user is watching), and release notes are reduced to plain text in main — the GitHub provider returns the release body as HTML and nothing renderer-side interprets markup off the network.
- 2026-09-01 — **The skipped version is read once at the top of a check, not inside `announce`.** This was a real bug caught by the unit suite: `update-available` fires *while* `checkForUpdates()` is still running, so an `await` on settings inside the announcement settled after the check had already concluded "nothing newer", and the announcement was lost. `this.checking` is assigned synchronously for the same class of reason — the settings read that precedes the network call is I/O, and two clicks a millisecond apart would otherwise both get past the coalescing guard.
- 2026-09-01 — **Settings → About now shows `app.getVersion()`**, arriving on the update status, rather than the string `0.1.0` that had been typed into the renderer since the first week and was four releases stale. The smoke step `settings-updates` asserts the page's version against `package.json`, so it cannot go stale again silently — and asserts the `off` posture end to end: a build that cannot update says so and offers no button that could only fail.
