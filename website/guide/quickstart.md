# Quickstart

One pass through the whole loop, using the paper SUNA ships with: open a project, read it, edit it, look at a figure, cite something, comment on it, and export it against a journal's rules.

This takes about ten minutes with the app open beside these instructions. You need a running SUNA — if you do not have one yet, start at [Install](/guide/install), which covers running it from source on macOS.

## 1. Open the example project

Launch SUNA. The **Welcome** tab opens by default, with five buttons and — once you have opened something — a list of recent projects. Click **Open example**.

<figure class="shot">
  <img src="/shots/welcome.webp" alt="The Welcome tab, headed 'A workspace for the whole paper', with five buttons in a row: Create project, Open project, Open example, Set up project and Import .docx. Below them, the recent-projects area is empty on a first run." />
  <figcaption>The Welcome tab. Open example is the fastest way in — it needs no folder, no journal choice, and no AI provider. Once you have opened projects, they are listed under the buttons.</figcaption>
</figure>

**Open example** never edits the demo shipped inside the app. It copies `examples/demo-paper/` to `~/Library/Application Support/@suna/desktop/example-project`, runs `git init` on the copy with an initial commit, and reuses that copy every time afterwards. Delete the directory to start fresh.

The project you now have open is a short astronomy paper on ram-pressure stripping, set to the **Nature Astronomy** profile. It is a plain folder: `suna.json`, `manuscript/`, `figures/`, `code/`, `data/`, `analysis/`, `results/`, `output/` — all text, all under git.

## 2. Read the manuscript

Click **Manuscript** in the left activity rail. That both switches the sidebar to the outline and opens the combined **Manuscript** tab.

<figure class="shot">
  <img src="/shots/manuscript-reading.webp" alt="The Manuscript tab in Reading mode: a typeset title page with authors and superscript affiliations, body prose with superscript numeric citations, and a KaTeX-rendered display equation." />
  <figcaption>Reading mode. The title page, citation style and equation numbering are all derived from the active profile and <code>manuscript.json</code> — none of it is typed into the prose.</figcaption>
</figure>

The tab is one document: the title page (authors and affiliations from `authors.json`, abstract, significance), the whole of `manuscript.md`, and a references page numbered by first appearance. The sidebar outline is derived from the Markdown headings; clicking a row scrolls the tab to that section.

The prose is one flat file. There is no `sections/` directory, and no figure number, table number or citation number is stored anywhere — SUNA derives all of them at render time from the order things first appear.

## 3. Edit a sentence

Reading mode is an editable live preview, not a read-only render. Click into a paragraph in the Results section and change a word.

Press <kbd>⌘E</kbd> to switch to **Source** mode and see what you actually changed — raw SciMark: `[@gunn1972]` for a citation, `@fig:fig-spectrum` for a cross-reference, `![[fig:fig-spectrum]]` on its own line for a managed figure. <kbd>⌘E</kbd> again returns to Reading.

Autosave is on by default and writes a second after you stop typing; <kbd>⌘S</kbd> saves immediately. <kbd>⌘Z</kbd> undoes.

::: tip One buffer, many views
Open `manuscript/manuscript.md` from the Explorer and you get a second live view of the same document, not a copy. Typing in one mirrors instantly in the other, with a single dirty state and a single save path.
:::

## 4. Look at a figure

Click **Figures** in the activity rail, then the `fig-spectrum` card. The figure opens in the canvas.

<figure class="shot">
  <img src="/shots/canvas.webp" alt="The figure canvas: a vertical tool rail on the left, a LAYERS tree, a millimetre-ruled artboard holding a two-panel plot, and a right rail with Align, Figure, Palette, Agent and Export sections." />
  <figcaption>The canvas edits <code>figures/fig-spectrum/figure.svg</code> in place. The artboard is measured in millimetres because journal figure widths are stated in millimetres.</figcaption>
</figure>

Press <kbd>V</kbd> for the select tool and click a text label. The PROPERTIES rail on the right shows what you can change; the LAYERS tree on the left shows the SVG's own structure, because the document model *is* the SVG file — there is no separate scene graph and no import step.

Nudge the label with the arrow keys (<kbd>⇧</kbd> multiplies by ten), then <kbd>⌘Z</kbd> to put it back. <kbd>⌘S</kbd> saves. More at [the canvas](/figures/canvas); the figure here was generated by a script that lives beside it, which is [Figures from code](/figures/from-code).

## 5. Insert a citation

Go back to the Manuscript tab, put the cursor at the end of a sentence, and press <kbd>⌘⇧K</kbd>.

A small palette opens at the cursor with a **Search references…** field listing every entry in `manuscript/references.bib`. Type a few letters of an author or title, then press <kbd>⏎</kbd>. SUNA inserts `[@key]` at the cursor.

Switch to Reading mode and the same key renders in the active profile's style — a superscript number under Nature Astronomy, author–year under another. The style is never written into the prose, so changing journals changes every citation at once. See [References](/writing/references).

## 6. Leave a comment

Select a sentence you are unsure about and press <kbd>⌘⇧M</kbd>. The comments rail opens on the right with a composer reading **Add a comment…**. Type a note and click **Comment**.

<kbd>⌘⌥M</kbd> toggles the rail. Threads are sorted by position in the document, and each carries **Reply** and **Resolve**. Resolved threads move out of the working list and can be reopened.

Comments live in `manuscript/comments.json`, anchored by surrounding text — the prose itself is never marked up, so a comment survives edits around it and is marked `detached` rather than deleted if its anchor truly goes away. See [Comments](/writing/comments).

::: info Resolving is a human's move
An AI agent can add comments and reply to them through SUNA's MCP interface, but there is no verb that resolves one. Closing a thread is always your decision. See [MCP](/ai/mcp).
:::

## 7. Export, and read the compliance check

Press <kbd>⌘⇧P</kbd> and run **Export Manuscript (Word/PDF)…**. The **Export** tab opens.

<figure class="shot">
  <img src="/shots/export.webp" alt="The Export tab: Document, Format, Journal profile and Article type pickers, Double spacing / Line numbers / Page numbers checkboxes, a COMPLIANCE CHECK section listing two errors, and a journal REQUIREMENTS panel with source links." />
  <figcaption>Compliance runs before the export, not after. Each rule in the Requirements panel carries the guideline URL it came from.</figcaption>
</figure>

Set **Document** to Manuscript, **Format** to Word (.docx), and leave **Journal profile** on the project's own. Pick an **Article type** to narrow the limits to that type.

The **Compliance check** section runs the profile's checkers against the manuscript and lists what it finds — abstract over the word limit, a required section missing. The findings are warnings: SUNA flags, and never silently reformats or blocks the export. A clean manuscript reads "No issues found."

The **Requirements** panel beside it derives the journal's stated submission rules from the profile. Where the journal states nothing, it says "not stated" rather than inventing a value.

Click **Export Word**. The file lands in the project's `output/` folder; nothing in your sources is touched. Formats are Word, PDF and Web page — see [Export](/publishing/export) and [Compliance](/publishing/compliance).

::: warning Not built yet
Compliance diagnostics are surfaced only in this Export tab. There is no in-manuscript indicator that warns you about a long abstract while you write it.
:::
